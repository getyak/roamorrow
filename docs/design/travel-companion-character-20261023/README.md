2026-10-23。用户已在本聊天选择 C，并要求后续品牌调性沿用 C。本目录保留最初设计与生成来源；随后已接入正式 iOS App。执行范围见[原生交付摘要](../../qa/companion-ios-20261023/PUBLISHED_ACCEPTANCE.md)。完整截图与原始报告留在本机 `docs/qa/companion-ios-20261023/round5/`，网页预览仍只是设计演示。

## 已确认的方向

角色是一颗有表情的小石头：苔绿色的不规则圆润身体、奶油色脸、深色圆眼、赭黄围巾。安静、亲近，带一点好奇。没有机械感，不堆叠旅行道具。角色名暂不新增，也不重新显示此前要求移除的“同路”标题。

探索图中的 A 是平面旅人，B 是立体人物，C 是抽象小角色；用户选 C。后续可以继续调整材质和比例，但不应突然换成写实人物、机器人或另一套角色。

## 品牌应用建议

以下为设计建议色值，独立于生成图片内部的像素取色：

| 用途   | 色值      | 用法                         |
| ------ | --------- | ---------------------------- |
| 苔绿   | `#73774D` | 角色身体与小面积品牌识别     |
| 奶油白 | `#F1E5C7` | 角色脸与柔和衬底             |
| 赭黄   | `#C58D32` | 围巾、少量强调，避免铺满界面 |
| 深林绿 | `#24392C` | 正文、必要的高对比图标       |
| 暖纸白 | `#FAF7F0` | 画布                         |

识别主要靠轮廓、脸和围巾。聊天头像 30–32pt，整组回复出现一次；空状态可放大到 100–140pt。应用图标使用同一角色的脸和围巾近景，正式导出需单独检查 24/32/48pt 的眼睛与轮廓清晰度。生成的位图原稿不能代替最终图标尺寸验收。

现有“此刻／附近”和右侧操作位置沿用。对话里加入角色不意味着增加一行导航、浮动吉祥物或长驻品牌标题。地图图钉、收藏和地点类别仍优先使用容易识别的功能图形，不把所有图标都替换成角色。

## 三条短消息

用户截图中的内容适合缩写后排为一组，而不是机械地将每一段变成一条消息。示例：

> 好，那今天就先不安排什么。
>
> 找个舒服的位置坐一会儿，什么都不做也可以。
>
> 想聊聊今天，还是先安静一会儿？

与本轮问题无关的城市／定位说明从示例中移除。通常 1–3 个气泡，每个气泡完成一个意思；简短回复保持一条，列表、代码、完整引文和需要连续解释的内容不硬拆。

多个气泡仍属于同一轮回复：同一个原始条目与时间、来源、重试和引用身份，不制造三次送达或三个人类打字事件。新回复可结构化生成或按完整语义段落呈现；流式内容不应逐 token 改写既有气泡。旧消息保持原文，不用此示例覆盖历史。

## 动作建议

下面保留原始动作建议，不是已全部实现的状态表，也不是对 Grok 动画参数的测量。

| 状态     | 角色动作                             | 信息表达                         |
| -------- | ------------------------------------ | -------------------------------- |
| 安静     | 静止为主，可偶尔轻眨眼               | 不抢阅读注意力                   |
| 收到消息 | 一次幅度约 2° 的轻抬头，约 350ms     | 已接到这次操作                   |
| 处理消息 | 约 3° 的轻歪头与微小呼吸，不带动气泡 | 只在实际请求仍进行时出现         |
| 回复完成 | 回正，一次轻点头后停下               | 绑定真实完成事件                 |
| 需要重试 | 停止动作，保留清晰文字与重试入口     | 失败不能靠表情或颜色独自表达     |
| 正在录音 | 轻微朝向输入区，配真实录音时长／音量 | 仅麦克风已授权且真的在录制时使用 |

不随意模拟“悲伤”“想念”“吃醋”等关系或情绪事实。文本生成期间不假装口型说话；未来若有语音朗读，口型只能跟随真实音频。角色的性格主要由稳定的语气和举止形成。

原生接入时以请求／工具执行、真实录音、播放与失败状态驱动。现有 `CompanionHomeEntry.Status` 只有 queued / working / delivered / failed，不能凭一个 working 值虚构“正在搜索网页”；更细状态必须来自实际工具事件。不能用永久循环掩盖挂起、失败或超时。

减少动态效果时使用静止角色和简短状态文字；滚出屏幕、进入后台、低电量或用户关闭角色动作时停止非必要动画。VoiceOver 只在状态确实变化时提示一次，装饰头像不重复朗读，不把每个气泡的头像都变成焦点。字号放大时头像保持小尺寸，把宽度留给文字。

## 已接入 iOS 的范围

正式对话使用同一份 C 透明原稿，32pt、每组回复一次；画布与接收气泡采用暖纸白、柔和苔绿。现有导航、地图功能图标和媒体入口沿用。应用主图标尚未替换，后续品牌资产以本目录的 C 轮廓、脸和围巾为统一依据。

当前动作保持克制：只有真实请求进行时轻歪头与微小呼吸；完成、失败、取消和冷启动恢复后静止。动作同时受真实可见滚动视口、前台、系统减少动态效果与低电量状态约束。没有常驻眨眼、假口型或虚构搜索状态；录音仍由实际时长和已有控件表达。

普通回复按 2–3 个完整语义段落呈现，短回复保留一条；列表、链接、引用、代码和长文不硬拆。持久化仍保留一个原始条目，引用、复制、重试与来源共同指向整轮回复。没有修改已有原话或制造多次送达。

用户已明确选择先交付模拟器结果，完整 VoiceOver 手势、转子和朗读顺序待连接真机后补验；实际截图、自动审计与隔离探针分别记录。

## 调研依据与证据边界

- [Grok Bot 官方设计文章](https://x.ai/news/designing-grok-bot)，2026-09-03：以简洁造型和眼睛建立身份，用头像本身区分空闲、工作、等待、受阻、思考和完成。文章提供六状态交互演示。本文仅借鉴“角色承载状态”的原则，未复制其眼睛或造型。
- [Grok Bot 官方更新记录](https://x.ai/changelog/bot)：提到工作中没有新进展时使用动态头像，以及侧栏和活动行的头像动作优化。
- [Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion)：动作应有目的、简短并可选；状态不能仅靠动作表达。

实际打开了官方文章，确认六状态控件存在。此浏览器中的演示角色仅显示黑色圆形，未据此声称测得眼睛、频率或歪头角度；上述角度与节奏均为原创方案。最初将用户截图猜为 Poe 已在聊天中纠正，最终依据是 Grok Bot 官方文章。
