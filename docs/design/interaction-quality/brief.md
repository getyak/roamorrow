# Web 与 iOS 交互品质提升

日期：2026-10-16（Asia/Shanghai）。基线：924f09a4。

用户目标：列出全部按钮与功能，逐项分析品味、观感、点击、状态、流程与边框注意力；优化 Web 官网及应用，优先原生 iOS；由独立角色盘点、实现和评分，目标每项超过 96。

## 产品与设计约束

服务独自到达陌生城市、需要决定下一步去哪的旅行者。核心单位是 Experience，地图是空间上下文；保留现有工作区与导航架构，不添加 tabs/drawer 或新的后端/商业承诺。保留暖琥珀品牌（#FAF8F6、#FFFFFF、#1F1A14、#6D6358、#5D3000、#C9A677），暗色使用已有 warm dark neutrals。iOS 使用原生语义字体/缩放，Web 沿用现有品牌字体但减少大写 eyebrow 和装饰性编号。

视觉层级：一个当前主动作；次动作使用低干扰填充或文本，边框只表达分组、可编辑或选中状态；图案来自指南针方位、路线和真实体验结构。状态反馈先于装饰。动效回答动作，减少持续脉冲与夸张缩放；尊重减少动态效果和增加对比度。

## 官网页面分支

A「随身方向」：在同一空间内把城市、此刻体验、下一步动作串起来。Hero 的实质证据是可进入 Web 的地图体验；中段展示从地图到体验到行动的联系。叙事布局：明确下一步 → 产品证据 → 可信边界 → 选择版本。记忆点是路线/方向，避免 SaaS 卡片矩阵。

B「旅途手记」：把旅途中一天作为叙事顺序。Hero 以一天摘要起笔，中段按晨/午/暮的体验与记录展开，再导向地图。记忆点是私人旅途记录，避免模板式报刊排版。

保留 A 为与现有 map-first 定位最接近的领先方向，B 为视觉比较的挑战方案。需要渲染证据后才能确认选择；不凭换色认定方向不同。两条分支不更改产品事实、价格或数据能力。

## 分工与验收

- inventory agent：完整源码候选、按页面归并的功能清单、状态/目的地/源码位置；候选数不等于按钮数。
- Pi + MiMo Pro：独立 worktree 编码实现与局部测试；不递归委派、不修改外部资源。
- independent reviewer：按清单评估扣分项、代码和证据；根代理负责原生构建、真实浏览器与模拟器验证。

功能评分与审美判断分开。量化维度按独立scorecard统一：可理解性15、层级/注意力15、触控与键盘20、状态反馈15、流程恢复与保留15、无障碍与动效10、产品一致性与信任10。源码推断标 provisional，未实测标 not_verified；单项不得用平均分掩盖阻断。品味采用截图 A/B 与具体理由，不把自编分数当成用户研究。96 是目标，不是完成声明。

## 外部依据

仅提取机制，不复制视觉身份：[Apple 按钮规范](https://developer.apple.com/design/human-interface-guidelines/buttons)、[Apple Maps](https://www.apple.com/maps/)、[Komoot 路线规划](https://support.komoot.com/hc/en-us/articles/4403138423066)、[AllTrails](https://www.alltrails.com/)。本地 UI/UX 检索强调44点触控、焦点可见、语义控件、动态字体和减少动态效果。

## 初步阻断

官网占位 App Store 链接、移动导航缺失、装饰 mock 中的无动作 button；Web 签到失败无提示、语音只有 pointer 操作；iOS 行程设置入口空动作、录音态缺停止的可访问操作、照片删除热区过小。详细证据由 inventory/review 文档提供。

## 渲染比较后的选择

A/B 已在桌面1280与手机390宽渲染。选择 A：首屏主动作在产品预览之前即可到达，地图内的路线与体验卡揭示空间→证据→行动的机制；B的入口位于三段时间叙事后，内容先于操作且长页更明显。A的中段用连续线表达同一决策的三个步骤；B三段独立条目更像手记。B作为挑战者保留。A仍有风险：示意地图不可冒充实时推荐，预览必须明确标注；需要真实可用入口支撑。已将选择及约束交给实现者。

## Web 本机环境观察

实际进入 /app：列表可加载5条种子降级体验，底图因本机没有有效Mapbox token最终空白，console明确报token required。此项是本机环境与恢复体验问题，不能推断线上也缺配置。正式验收需保留可用列表与诚实地图不可用提示，不能伪造token或将示意图冒充实时地图。缺密钥不应让主入口没有方向。未读取/复制私密环境，未授予位置/麦克风权限。
