## 四个入口各自负责什么

| 入口 | 默认内容                                  | 保留的状态                                |
| ---- | ----------------------------------------- | ----------------------------------------- |
| 对话 | 当前旅程最近的对话，首次使用显示简短起点  | 会话 ID、消息、草稿、下一问范围、阅读位置 |
| 地图 | 独立可达的一张地图，顶部切「附近 / 收藏」 | 模式、筛选、地图位置、选点、来源返回信息  |
| 行程 | 用户已确认的安排及其版本                  | 已确认站点、时间、来源和撤销信息          |
| 我的 | 旅行记忆、旅程档案、权限与隐私            | 各项设置及授权状态                        |

地图从回答进入时展示该回答的候选；从底部导航进入时允许独立浏览。它们使用同一个地图目的地，不再叠一层功能重复的全屏地图。切换入口先结束输入焦点，草稿不清空；键盘出现时导航让位，收起后恢复。

## 核心路径：回答 → 地图 → 同一段对话

1. **从回答进入。** 点击消息内的「在地图上看」，保存来源会话 ID、消息 ID、消息内候选及当时的阅读锚点、草稿和下一问范围。地图高亮这一条回答的候选，默认选中消息中的当前候选，显示「来自这条回答」和可返回的来源入口。
2. **地图上选点。** 地图选择、分类筛选、收藏切换和视区变化只更新地图浏览状态。卡片展示所选体验的理由、来源、限制与待核实项，不把地图当前选点写回旧消息。打开另一站时，来源与资料必须跟着所选体验切换。
3. **聊聊这里。** 点击明确按钮才把所选体验设为下一问范围。若来源仍可恢复，回到原会话和原阅读位置，保留草稿，并在输入框上方显示可移除的「关于 Parkside Café」。不自动发送，不替换原草稿，不重写旧推荐。
4. **继续提问。** 用户可以编辑草稿、移除范围或发送。发送时把本次范围记录在这一次新提问上；之后地图再次选点不能改变这条已发送问题的归属。新回复追加到同一会话。

普通「返回来源」只恢复来源，不附加新范围；「聊聊这里」才改变下一问范围。设计板第三屏使用无键盘的 `scoped` 状态便于评审，短片用 `typing-scoped` 展示范围与输入框的关系；它不表示点击按钮会擅自弹出原生键盘。

## 来源丢失时怎么回退

来源身份必须由 `{conversationId, messageId}` 及必要的内容版本确定，不能用全局“当前对话”或数组下标替代。来源链接是导航关系，体验资料来源是事实证据，两个入口分别命名。

| 情况                                   | 行为                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| 来源消息仍在                           | 恢复原会话、消息附近阅读位置与草稿；「聊聊这里」再设置下一问范围                           |
| 会话可恢复，消息或锚点已失效           | 恢复同一会话，说明原消息不可定位；使用可用的相邻位置或最近消息，不假装精确回到原处         |
| 会话已删除、不可访问或不属于当前旅程   | 保留地图选点，明确说明不能返回；给出「在当前对话聊聊」与「新建对话」，由用户选择后携带范围 |
| 没有来源，独立进入地图                 | 「聊聊这里」进入当前旅程的可用对话并设下一问范围；没有可用会话时新建，入口写明这一结果     |
| 用户已在别处更改同一会话草稿或阅读位置 | 按会话修订号核对，不用旧快照覆盖较新的内容；保留新草稿并说明范围变化                       |

回退不能静默跳到一个新线程并声称“回到刚才”。已删除会话不从地图缓存重建，跨账号、跨旅程或失去访问权限的历史不能带入当前范围。原型的页面内状态只覆盖示例，持久化、并发恢复和访问控制留给正式实现验收。

## 附近与收藏

**附近**用于探索当前选定范围。它可以由当前位置、手动指定的城市/区域，或回答候选启动；来源与范围标签始终可见。从回答进入时，先保留候选集合，用户再明确切到更广的区域探索。

**收藏**是长期保留的 Experience，不等于今天的安排。默认展示当前城市收藏，并提供清楚的「当前城市 / 全部城市」范围切换。全部城市保留列表可达性，不能只展示当前视区内的点；远处的收藏可先在列表找到，再选择查看该城市或该体验的位置。距离未知时显示城市或区域，不伪造“离你几分钟”。

模式切换保留各自的筛选、选点和地图位置；当前选点不在新结果中时选择可见项或显示未选中状态，不留下与列表不一致的详情卡。收藏为空时解释用途并给出附近入口，全部城市无结果时显示真实空态。取消收藏只更新收藏状态，不删除历史推荐或行程。

## 位置、手动范围与筛选

- **位置授权前：** 首次进入地图可以先用旅程城市或演示范围，不把已有地图当作已定位。只有用户点击「当前位置」时才请求原生权限。
- **拒绝、受限或定位失败：** 保留地图和收藏可用，显示准确状态并提供手动选范围。拒绝后不反复触发权限框；需要系统设置时由用户明确打开。
- **手动范围：** 城市、区域或地图视区有可见标签。它影响接下来搜哪里，不修改旅程目的地、历史消息或已确认行程。切回当前位置也是显式动作。
- **分类：** 复用现有分类；分类与附近/收藏模式共同确定当前可见集合。切换筛选不调用模型、不自动写对话、不把“没有可见点”解释为整座城市没有此类体验。
- **体验信息：** 所选卡保留来源、限制和不便之处；营业时间、步行时长等未核实项写清楚。图钉示意和真实底图不能代替地址核对。

## 平移地图、刷新此区域与外部搜索

这三种动作产生的结果不同，界面要分别表达。

| 动作                       | 发生什么                                                                       | 不应发生什么                                         |
| -------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------- |
| 平移或缩放                 | 改变相机位置，出现「搜索此区域」提示                                           | 不边拖边请求，不改回答候选或行程                     |
| 点击「搜索此区域」         | 明确用当前视区更新地图探索结果，保留来源返回入口；候选高亮可被新的探索集合替代 | 不篡改触发它的旧回答，也不把演示数据写成新检索结果   |
| 改分类或收藏范围           | 对当前模式的可用结果做筛选与选择协调                                           | 不暗中开启外部网站或发起模型搜索                     |
| 点击明确命名的外部搜索     | 单独交代将去哪里、搜索哪个对象，再执行该来源支持的搜索                         | 不将“本地筛选无结果”自动转为外部工具调用             |
| 点击「在 Apple Maps 打开」 | 对地址/坐标可用的所选体验，用户确认目标后显式打开外部地图                      | 不自动开始导航，不画未核验路线，不拿另一站坐标凑结果 |

地图平移刷新是本页探索，不等于网页搜索、实时营业核验或路线规划。原型中的按钮与提示只展示交互契约；真实工具能力、证据与失败路径以单独的工具评测结果为准。

## 独立地图与对话范围分开保存

地图状态可保存 `{mode, category, favoriteScope, camera, selectedExperienceId, resultIds}`；来源返回信息单独保存 `{conversationId, messageId, readingAnchor, revision}`。对话中的下一问范围是可移除的 `{kind: experience | area, value}`，跟当前会话草稿一起保存。

独立浏览不隐式创建对话、不更换下一问范围。只有「聊聊这里」或「聊聊这片区域」才携带明确范围进入对话。体验范围引用具体 Experience；区域范围记录视区及筛选并在标签中说明，不能把区域误当作某一个地点。移除范围只影响下一问，不能触发清历史或新建线程。

消息、地图浏览状态与已确认 Trip 分属各自的版本边界。收藏、筛选、返回、切 Tab 和删除范围都不能调用行程变更；加入/替换/调整仍经过预览、确认与可核对的执行结果。

## 早期原生迁移分析（legacy入口）

以下结论来自本轮读取的现有 Swift 源码，不是已经完成的迁移：

| 现有入口                                                                    | 当前行为                                                                                        | V4 需要的处理                                                                             |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `VoiceAgentOrchestrator.rebindContext(_:)`                                  | 先保存旧会话，生成新的 `persistedConversationId`，取消当前轮次，重建 system prompt 并清消息历史 | 不能直接用来实现“同一线程加下一问范围”；需要保留会话 ID 与历史的独立 scope 更新行为       |
| `VoiceAgentOrchestrator.restoreConversation(id:messages:scopedExperience:)` | 能恢复指定会话 ID、scope 与存储历史，异步 reseed 前会切换 readiness                             | 可作为来源恢复基础，仍需恢复草稿、阅读位置、消息关系和修订保护                            |
| `ChatSheet.restoreConversation(...)` 包装                                   | 调用上述恢复后再调用 `workspace.beginFollowing()`                                               | 现有历史入口会切到最近消息并清 anchor；需新增“从地图恢复来源”的入口，不能直接复用这个包装 |
| `ConversationWorkspaceState.beginFollowing()`                               | 设置跟随最新消息并将 `visibleAnchorId` 置空                                                     | 用户本来读历史时，应恢复有效来源 anchor；发送新消息或点“回到最新”才开始跟随               |

源码依据：[VoiceAgentOrchestrator](../../../apps/ios/SoloCompass/Services/VoiceAgentOrchestrator.swift)、[ChatSheet](../../../apps/ios/SoloCompass/Views/Chat/ChatSheet.swift)、[ConversationWorkspaceState](../../../apps/ios/SoloCompass/Models/ConversationWorkspaceState.swift)。正式实现还要处理异步恢复期间立即发送、旧轮次晚到结果、来源被删除及位置权限变化。

这部分是早期Compass/VoiceOrchestrator入口核对。当前实际默认入口为CompanionHomeView；正式实现复用其HomeStore、HomeAgent、媒体与本地快照，不把用户退回legacy根。实施与分层验证见[原生落地记录](../../qa/v4-native-20261030/README.md)。HTML本身仍不证明SwiftUI或真实工具验收。
