# 基于现有 iOS 的交互深化：一张地图，一条连续的任务

2026-10-30 · GET-324 / PR #685 · 设计提案 V2（已由 interaction-v3.md 的对话首页方向替代）

## 先给判断

最值得改的，是从意图到行动的路径。建议让用户在同一张地图上完成：**看附近 → 问一句 → 比较候选 → 预览调整 → 确认加入今天 → 看下一步**。

AI 成为一种输入和解释方式。它给出的结果落在可以比较、核对和操作的 Experience / 行程对象上。地图保留空间关系，底部任务面板负责当前任务，侧栏管理低频资料。这比把所有功能搬进一个侧栏，更贴合出行时单手、短时间、反复查看的使用方式。

V1 保留为产品方向与视频资料。本轮 V2 优先细化真实 App 的入口、切换、返回和状态反馈，视觉沿用当前棕金色系。V2 是当前建议采用的交互方向，尚未视为用户批准的原生实施。

## 首页的重新分工

建议保留地图作为唯一主场景，顶部只放当前城市/旅程、资料入口和定位。地图样式、筛选细项等次要操作按上下文出现。头像不再与城市、指南针、多个按钮一起争夺第一眼注意力。

底部采用一个任务面板。面板顶部只有「附近 / 今天」两个内容视图；下方是一条意图输入。它们属于同一地图上的内容切换，不引入新的根 TabView。用户不必先进入一个叫 AI 的地方才能提问。

- **附近**回答“现在可以做什么”。选中图钉或列表项，显示该体验的预览。
- **今天**回答“已经确定了什么，接下来做什么”。有行动时突出一个 next action；没有安排时提供轻入口，不造倒计时。
- **输入栏**在当前上下文内接受文字、语音和资料。输入不是一张独立首页。

底部不同时保留一条三项导航 Dock 和一条输入栏。常规字号下，空闲面板按内容约166–220pt；结果比较约440–580pt；长文和键盘输入可展开。数值是设计起点，需要原生大字号和小屏实测；不会用固定高度裁掉正文。

侧栏继续保留，负责旅程切换、已确认行程、票据、预算、跨趟偏好和权限设置。常用的“今天”和输入栏不藏进去。地图右侧也不常驻一列六七个图标。

## 五个具体交互

### 1. 点图钉：先看对象，再决定动作

点一个图钉，地图只进行一次必要的取景调整；同一 Experience ID 在图钉和卡片中同步高亮。第一层只给标题、耗时/距离的状态、适合原因和一项重要不便。推荐和事实区分，不用一个百分比取代来源。

这里的主动作是「放进今天」。次动作「问这家」把输入范围明确显示为该体验。收藏收在对象工具中，不能与“加入当前行程”写成意思相近的两个主按钮。长按可以有快捷操作，但完整功能也必须能轻点到达。

点击更多详情，在当前任务面板内展开；回退返回刚才的图钉、卡片、地图位置与阅读位置。

### 2. 问一句：结果可以操作，解释可以追溯

“找一家安静的咖啡馆，步行不超过20分钟”发送后，只在有真实任务状态时显示短进度，例如查询营业信息；没有调用相应能力就不能显示已经在查。用户可以取消，取消后保留已获得的有效资料，并明确结果不完整。

结果优先呈现2–3个有差别的候选，每项只写一个理由和一个关键限制。图钉编号与候选编号一致，点击任一方更新另一方。用户主动选中的项才成为当前查看对象，排名第一不等于已经替用户选好。

完整讨论与来源仍可展开，但不迫使用户读完整段对话才能找到动作。推荐卡的“放进今天”“比较”“调整条件”是对象动作，效果必须在地图和计划中可见。

输入范围必须始终可见：附近 / 这片地图 / 某个体验 / 当前旅程。清除范围后立刻改变标签。用户拖动地图只改变视野，出现「搜索这片区域」后由用户决定是否更换查询范围，不静默把旧问题改成另一片地方。

### 3. 加入今天：先预览影响，再写入

点「放进今天」先进入调整预览，显示新增的 Experience、建议时间、与原安排的冲突、步行和缓冲变化。原计划不动。用户调整时间后，影响说明随当前草稿重算。

确认时写同一份计划，按钮短暂进入保存状态，成功后变成今天的一站。失败则保留草稿与确认前的计划，并允许重试。返回比较不丢草稿；浏览另一个候选也不能悄悄改掉已确认安排。

“收藏”“保存计划”“开始导航”分别表达不同结果。确认一站不等于预订商家；打开导航不等于已经出发或到达。外部支付、改签、取消沿用 V1 的明确确认边界。

撤销只适用于可逆的计划修改，并验证当前版本。撤销生成一个新版本，不把版本号倒退。已有新变化时提示查看最新计划，不覆盖更新内容；已支付、已出票等行为不提供假的“撤销一切”。

### 4. 去执行：界面收敛到一个下一步

用户确认后，面板呈现“下一步 / 最晚出发 / ETA状态 / 主要动作”。默认只突出当前动作，后续安排仍在时间轴中。开始导航需要明确点击；打开外部地图后回来，仍看到同一个行动对象与计划版本。

时刻、位置、状态失效时显示最后核对时间与待核实项。没有数据就显示未知。可展开解释“为什么现在出发”，让用户看到从何计算出截止时间，但默认界面不变成计算表。

本轮可点击稿中的地点、距离和时间是 fixture，不具备真实路线计算或导航能力。

### 5. 说话：容易开始，也容易退出

点击麦克风后才请求权限并开始录音。短按开始/停止是可发现的主方式，长按说话作为加速方式；不能把长按当唯一入口。录音状态使用明确文案、转写与停止按钮，不只依赖光效。

转写在发送前可修改，可取消；取消保留原先输入的文字。收起面板、打开覆盖弹层、进入后台必须让录音与播报停止，同时保留会话。已有 `hibernationToken` 和输入状态可以复用。

拒绝麦克风权限后，输入框仍可用，并提供“继续打字”。不因缺权限阻断查看地图、已有安排或资料。

## 返回、键盘与手势：必须写成规则

| 操作                       | 期望行为                                                                         |
| -------------------------- | -------------------------------------------------------------------------------- |
| 打开输入键盘               | 输入靠近键盘上沿；暂让出次要工具，不叠放 Dock、输入栏和系统键盘                  |
| 收起键盘                   | 回到聚焦前的面板高度；用户期间手动选了高度时保留用户选择，沿用现有 revision 保护 |
| 拖动地图                   | 不新建聊天，不清空草稿，不抢回地图镜头；查询范围需明确更换                       |
| 拖动面板                   | 主要由手柄/标题区拥有手势；内容区滚动与地图平移各自独立                          |
| 面板中的列表滚动           | 已在历史位置时不被新消息强拉到底部；提供“新回复”入口，保留当前阅读位置           |
| 从详情或预览返回           | 回上一层内容、选中对象与面板高度；不一律回首页                                   |
| 点模态的关闭               | 退出整个临时任务；模态内的“返回”只退一步，两者文案不能混用                       |
| 展开侧栏                   | 键盘先收起；保留当前任务。关闭后回到原状态，不重置为地图默认画面                 |
| 切换旅程                   | 草稿与任务按 tripID 分开。不要把上一趟的地点上下文带进新旅程                     |
| 被新请求替代的旧请求晚返回 | 用请求标识与 Trip 版本阻止旧结果覆盖新任务；取消状态不能被旧成功回调改写         |
| 连续点击确认               | 同一次调整只提交一次；失败能重试，结果未知先查询，不把连点变成重复动作           |

`ConversationWorkspaceState` 已经把内容种类和面板高度分开，这一层值得保留。后续让 `selectedExperienceID`、草稿、候选集、已确认计划各有明确身份；当前查看哪个候选与计划采用哪一项不能共用一个可变字段。

## 弹层与信息层级

当前根页面有许多 sheet presenter，但这不等于运行时一定叠了多层；需要按实际调用逐项检查。设计上先约束为：普通任务在同一个面板内推进；身份授权、支付预览、导入核对等明确临时任务才开模态；一次只展示一个活动模态。

个人页、发现页、行程页之间不再靠弹层套弹层完成日常任务。确需多步骤的模态只保留一个 NavigationStack，退出时恢复原工作区。系统权限弹窗不会与自绘说明弹窗同时压住界面。[Apple Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)

地图的可见区域、图钉聚焦与控件避让要一起计算。当前 Map 的底部 safe-area 留白使用 collapsedHeight，后续应核查更高面板下的地图署名、路线关键点和导航控件，按实际遮挡量调整，避免把重要目标放在面板背后。

## 失败状态也属于主流程

| 状态                    | 用户看到什么                   | 可以继续做什么                                           |
| ----------------------- | ------------------------------ | -------------------------------------------------------- |
| 没有附近结果            | 说明当前范围和筛选条件         | 放宽一项条件、换区域、看收藏                             |
| 模型未连接 / 服务不可用 | “暂时无法生成新建议”与恢复入口 | 看已有体验、已有安排、手动添加；设置页再解释具体服务配置 |
| 营业时间未知            | 当前候选标注待核实             | 看来源；如仅保存计划，明确知道不确定性后再加入           |
| 行程保存失败            | 原计划保留，草稿仍在           | 重试或返回比较                                           |
| 离线                    | 已保存内容与更新时间           | 只读今天和关键资料；不可实时查的按钮解释原因             |
| 位置未授权              | 当前是手动区域                 | 输入城市/区域；不强制打开设置                            |
| 上下文过期              | “这条建议基于昨天/另一城市”    | 重新核对当前范围，旧内容作为历史保留                     |
| 已有计划冲突            | 哪一项时间/硬约束冲突          | 改时间、换候选；不只弹“操作失败”                         |

状态提示按当前任务的风险排序。航班变更和会影响付款的冲突优先于普通网络提示；最多一个主提示，其余收进状态详情，不让多个横幅挤掉地图。提示要说明恢复动作，不用内部错误码、工具函数名或供应商密钥说明占据首页。

## 视觉应该怎样配合交互

保留当前 `CT.accent #5D3000`、暖白表面与现有 Space/Radius/Motion 规范。变化来自信息层级和内容连续性，不依赖整套换色。地图和主要阅读表面分清；玻璃材质只用于短小控件，付款条款和来源正文用稳定不透明底色。

常规正文17pt，候选标题至少15–17pt；日期、来源为次级信息，也要在大字号时换行并可滚动。原型里的整机排版是概念，不是字体与触区的原生验收。点击目标至少44pt，符号旁有可理解的标签；图钉、候选项、选中状态既用颜色也用编号/文字表达。

主要内容切换以同一面板的高度与对象状态变化承接，避免整屏反复飞入。常规切换约0.25–0.35秒；Reduce Motion 下直接切换。键盘进出和面板还原沿系统节奏，不能每次重新跑一段品牌动画。[Apple Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields) 对底部可达的输入入口提供了参考，但本提案的内容组织是针对 Roamorrow 的设计判断。

## 如何落到现有代码

| 批次                   | 主要责任                                                 | 复用位置                                                          | 需要验证                                                     |
| ---------------------- | -------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------ |
| 第一批：减少重复入口   | 调整底部输入与内容入口、压缩空面板；上下文标签与回退规则 | WorkspaceDock / ConversationPanel / ChatInputBar / MapOverlayView | 地图可用面积、单手可达、草稿/附件/阅读锚点不丢               |

## 本轮交付与验证边界

新增 `interaction-v2/prototype.html` 可点击稿和三状态设计板，展示主路径及确认/冲突/撤销、语音转写示意、上下文和侧栏分工。本轮演示只管理一个可编辑的新增体验槽位：已有确认体验时，后续动作明确变成“替换这一站”或“调整这站时间”，在预览里点名旧安排并再次确认；不会伪装成无限新增行程的完整实现。撤销记录用一次即失效，恢复的原安排不会被第二次撤销清掉。提问范围按自己的 Experience ID 显示和读取，浏览候选不会改写范围。

数据只在页面内存中；刷新会重置。没有调用麦克风、位置、模型、真实商家、供应商预订或支付。

推荐后续用真实用户任务验证：从首页发问是否无需先选 AI 模式；能否说出当前提问范围；选候选后能否在地图上对应；预览返回是否没有改动计划；确认后是否可见下一步；拒绝权限是否还能继续。再做小屏、大字号、VoiceOver、键盘、离线与后台恢复的原生验证。

本轮未更改 SwiftUI 产品代码，也不把浏览器概念验证等同 Simulator、真机或生产验收。
