# 交互 V3：打开就是对话

2026-10-30 · GET-324 / PR #685 · 本方向已由 interaction-v4.md 细化为「对话 / 地图 / 行程 / 我的」，收藏移入地图

## 用户已经明确的方向

用户否定 V2，把 Muse 截图指定为结构参考：打开直接进入对话，地图只是支持呈现的一种方式，并继续打磨输入框下面的导航栏。这是对产品入口的明确调整，优先于仓库旧有的 map-first 默认约束。本轮仍交付可评审的交互设计，不把新设计表述为已经上线的原生 App。

参考范围是截图可见的界面结构：轻薄的顶部控件、中央伙伴形象、可连续阅读的对话、独立悬浮输入框和下方胶囊导航。没有据此推断 Muse 未展示的功能和行为。参考图中的聊天、账号和业务内容不进入原型或仓库；只使用本项目的旅行场景与现有 CompanionCharacter 形象。

本轮已同步远端 `main` 至 `20f2ff8b`。原生依据仍是现有 `ConversationWorkspaceState`、`ConversationPanel`、`ChatInputBar`、`WorkspaceDock`、`DiscoverWorkspaceView`、`Itinerary` 和 `MeSheet`。没有改 SwiftUI 产品代码。

## 首页怎么改变

启动恢复当前旅程最近的对话，并定位到最近回复。第一次使用或新对话显示简短招呼与两项具体起点，不放功能目录、万能提问清单或空白仪表盘。

顶部左侧管理对话记录，中央保留已有旅行伙伴，右侧显示当前旅程。对话正文保持完整；体验候选、来源、小地图和行程调整卡是消息里的对象。用户不必先进入“AI 模式”。

地图有三个层级：回答中的小地图、点开后的全屏地图、从行程单站查看位置。退出后回到触发它的对话、收藏或行程及阅读位置。它不再承担一级导航，也不再作为启动后的背景铺满屏幕。正式路线与系统导航仍需核对目的地后单独接入。

## 输入框下面为什么选四项

| 方案                             | 优点                                             | 代价                                           | 本轮判断               |
| -------------------------------- | ------------------------------------------------ | ---------------------------------------------- | ---------------------- |
| 对话 / 行程 / 我的               | 最轻，内容区域多                                 | 收藏需多走一层；规划中积累的候选不容易重新找到 | 可作为轻量版，暂不优先 |
| **对话 / 行程 / 收藏 / 我的**    | 表达、执行、保留和个人资料各有入口，文字容易理解 | 要明确收藏与加入行程的差别                     | **本轮建议**           |
| 对话 / 地图 / 行程 / 收藏 / 我的 | 地图随时可达                                     | 占用一个同级目的地，又把辅助表达抬回产品中心   | 与用户这次方向不符     |

四项始终存在，不因某页没有内容而消失。收藏空时解释用途并给回对话的入口。选择态由浅色胶囊、符号和文字共同表达。正式 SwiftUI 使用 SF Symbols 与短标签；本轮 HTML 使用 Lucide 作跨平台对应。[Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)

| 入口 | 回答的问题                     | 放什么                                    | 不混入什么                   |
| ---- | ------------------------------ | ----------------------------------------- | ---------------------------- |
| 对话 | 我现在想做什么？               | 对话、体验选择、核对与确认卡              | 长期设置目录                 |
| 行程 | 已经决定什么，下一步是什么？   | 当前 Trip、今天的时间轴、票据、预算与来源 | 未确认推荐作为既定安排       |
| 收藏 | 以后也许想去哪里？             | 可再次讨论的 Experience                   | 自动替用户加入今天           |
| 我的 | 你记得我什么，我允许你做什么？ | 旅行记忆、旅程档案、权限与隐私、离线资料  | 把付款与证件信息写进聊天记忆 |

“今天”是行程的默认内容，不单独再占一个 Tab。发现融入自然语言推荐与收藏，不保留一个泛推荐信息流。记忆放在我的，票据与预算从当前行程进入，避免同时出现“资料”“工具”“更多”等含义接近的入口。

## 输入框与导航的关系

- **未输入：** 393×852pt 概念画面中，导航高70pt，距底部25pt；输入框最小高56pt，与导航间隔9pt。两块表面各自成组，输入控件不混成导航的第五项。
- **正在输入：** 导航收起，输入框贴近键盘上沿。输入增长至多四行，正文让出可视区域。若原来读到最新消息，继续跟随底部；若在看历史，不强拉到底。
- **收起键盘：** 草稿、提问范围和阅读位置保留，导航恢复。切换内容先结束输入焦点，但不清空草稿。
- **发送按钮：** 无文本时显示麦克风；有文本时同一位置切成发送。中文输入法确认候选字不会触发发送。发送按下期间不因键盘收起而移动目标。
- **附件：** 左侧加号只管图片、文件和确认信。不要同时塞入新建行程、支付、换城市等导航任务。
- **语音：** 转写先可编辑，再由用户发送；取消保留原草稿。原型仅展示转写与键盘位置，不录音、不调用原生键盘。

正式实现以键盘 safe area、FocusState 和已有 workspace 的 revision 保护为准。截图里的键盘高度只是示意；它不能代替中文输入法、外接键盘、小屏或 Dynamic Type 验收。iOS 26 材质与系统栏行为需做版本判断，iOS 17–25 保留稳定、可读的材质回退；不把 `tabBarMinimizeBehavior` 当作完整的键盘状态管理。[SwiftUI updates](https://developer.apple.com/documentation/updates/swiftui)

## 对话成为主场景后，不能丢掉的边界

1. **对话保留。** 每段对话有 ID、消息数组、草稿、范围与阅读位置。新消息追加；旧回答、旧推荐理由和“无法核实”结论不能被后续操作重写。开始新对话可以在记录中找回前文，已确认 Trip 不随对话清空。
2. **对象有归属。** 每条推荐保存自己的选择与范围。对话地图只更新触发它的那条推荐；从收藏或行程打开的地图不修改任何聊天消息。来源绑定消息或行程项 ID，不读取某个全局“当前选中地点”代替。
3. **预览再确认。** 加入、调整、替换先给出差异与原安排；检查最早到达、时间重叠和未核实项。保存后进入行程；失败保留草稿。一次有效撤销恢复旧计划并形成新版本。
4. **建议与事实分开。** 对话中的漂亮卡片不能代表已营业、已出票或已付款。营业未知要可见；地图没有正确地址就说明待核实，不展示另一站的坐标。
5. **花钱单独确认。** 支付、改签、取消使用金额、币种、对象、退款政策和执行结果明确的确认流程。对话里的“好”“行”不能在另一个对象或过期报价上复用。本轮没有实现任何真实执行工具。
6. **模态一次一件事。** 地图、资料、语音转写、确认预览都接管焦点，关闭后恢复来源。打开时先收键盘，Tab 不跳到背景，Escape 可以退出。

原型为两个虚构咖啡体验、一个原有博物馆安排以及一个可新增/替换的槽位。当前时钟固定12:40，仅供判断演示时间是否可达。没有实现多时区、多日任意增删、真实位置、营业查询、账户或持久化；刷新重置。

## 视觉打磨的具体取舍

采用近白背景、浅灰绿回复面、低饱和橄榄色选择态。已有旅行伙伴提供识别度，输入和导航采用独立、轻薄的浮层；正文和条款用稳定实底。常规对话17pt，候选标题16pt，导航标签11pt；来源是次级信息，但仍保持可读对比度。

符号统一一套，主导航和输入按钮有至少44pt触区。顶部不再排列筛选、指南针、头像、品牌、城市和多个操作。回答里只给两个有差别的候选，选中项给一句理由，来源按需打开。主要动作只有“放进今天”，收藏使用独立的书签按钮，不与加入行程混淆。

默认优先清楚的按下反馈与状态变化。本轮短片是12秒的三个 UI 状态演示，不伪装成已完成的原生流体动画或真实系统录屏。正式版本再用可中断的系统动效验证键盘、页面和地图衔接，并提供 Reduce Motion / Reduce Transparency 回退。

## 如何落到现有 iOS

| 批次             | 代码与行为                                                                                                                              | 验收                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 先做对话首页     | 调整 CompassMapView 的主场景组合；复用 ConversationPanel、ChatInputBar 与 ConversationWorkspaceState，默认恢复 `.ask`；地图变为按需呈现 | 启动、冷恢复、键盘、中文输入法、语音退出、草稿和阅读位置 |
| 再改导航         | WorkspaceDock 转为明确内容目的地；收藏复用现有 Experience；MeSheet 收敛个人资料与权限                                                   | 四入口稳定、空状态、返回、不会因视图销毁丢对话           |
| 再接对象卡       | 候选和来源绑定 message/Experience ID；地图所有权和执行对象明确                                                                          | 浏览收藏不改旧消息；来源不串对象；旧响应不覆盖新任务     |
| 最后做 Trip 执行 | Itinerary 扩充逐段时间与版本、预览变更、最早到达与冲突校验、权限和支付确认                                                              | TS↔Swift 兼容、幂等、失败重试、离线与真实系统能力        |

先用真机验证最常见的一分钟任务：“打开就说一句 → 比较两个选择 → 在地图上看 → 返回 → 确认放进今天”。再验证“输入中切到行程再回来”“拒绝麦克风后继续打字”“回看旧建议时收到新回复”等恢复路径。
